日期：2026-10-06。正式站点：https://dou.love765.me/。

## 范围

迁移应用、量化算法、轮廓处理、拼豆预览、图纸绘制、PNG 编码及两个 Worker 到 `src/*.ts`，启用 TypeScript 严格检查。共享图纸、RGB/Lab、预览状态和 Worker 消息类型放在 `src/types.ts`。没有用 `any`、`@ts-ignore` 或 `@ts-nocheck` 绕过检查；不引入 React。

Vite 只用于开发和构建，浏览器不加载构建依赖。生产发布仅上传 `dist/`，JS、CSS、图标及 Worker 使用内容版本号；不发布 `.ts`、源码映射、测试或开发工具。保留默认 32 颗、MARD 221 色、本地图片处理、现有图案算法和粉色樱花/橙猫设计。

## 1. 构建体积、压缩与缓存

迁移前保存旧应用的全部 10 个 JS 文件及 CSS；迁移后统计正式构建的主脚本、生成 Worker、导出 Worker 及 CSS。覆盖完整脚本/样式集合，不是仅比较首页脚本。

| 指标 | 迁移前 | 迁移后 |
| --- | ---: | ---: |
| JS/CSS 文件数 | 11 | 4 |
| 未压缩字节 | 66,240 | 51,144 |
| 正式 HTTPS 请求的 gzip 响应体字节 | 22,515 | 19,878 |

未压缩体积减少 **22.8%**，已压缩响应体减少 **11.7%**。旧站本来就支持 gzip，不能将新 gzip 大小与旧未压缩大小比较并宣称大幅提速。新版本还保留了 MARD 的 MIT 许可，并新增错误、可访问性和内存控制逻辑。

逐个验证正式资源：

- HTML 返回 `Cache-Control: no-cache`，每次访问重新验证。
- 带版本号的 JS/CSS/SVG 返回 `public, max-age=31536000, immutable`。
- 请求 gzip 时返回 `Content-Encoding: gzip`、`Vary: Accept-Encoding`，响应体大小与本机构建的 `.gz` 一致。
- 用资源 ETag 发起条件请求，返回 304。
- 资源响应仍保留 CSP 和 `X-Content-Type-Options`。
- 压缩测试验证解压后的内容完全相同，多次构建压缩结果确定。

这些结果证明资源体积、请求组织和缓存策略改善，不证明首屏时间同比减少 11.7%。没有进行统一网络条件下的 Lighthouse 或多设备加载速度对比。

## 2. 预览内存与缓存

在真实浏览器中上传正方形图片，生成 160×160 图纸，分别把四种预览放大到每格 32px。以前最大网格画布为 5,176×5,176，即 26,790,976 像素；现在所有预览内部画布都不超过 **8,000,000 像素**，显示宽度仍分别为 5,176px（网格）和 5,120px（其他模式）。图纸索引、计数和导出不因此改变。

像素预览首次建立缓存后，连续 10 次缩放不再创建像素画布；生成新图纸时，创建新的采样画布和像素缓存。这说明重复缩放避免了重复分配，不代表页面总内存被限制为 32MB。原图、浏览器解码和拼豆精灵仍占用额外内存。

## 3. 交互与可靠性

- 读取新图片期间改设置，不再生成上一张图片；解码完成后使用最新设置。
- 生成 Worker 超过 45 秒无结果时，解除忙碌状态、提示错误并禁止导出过期结果；重新生成可恢复。
- 保留导出独立 Worker、重复点击保护、分批回退和快照文件名/尺寸。
- 手机主要按钮至少 44px 高，保留 16px 选择框和浏览器缩放能力。
- 增加键盘跳到预览、画布键盘滚动、可见焦点、滑块易读值、错误关闭按钮和 Escape 关闭。
- 增加 canonical、Open Graph、robots.txt、sitemap.xml 和禁用 JavaScript 说明，不加载追踪统计。

可访问性检查覆盖上述具体交互，不是完整 WCAG 合规认证。
